# План: КП-студия как веб-сервис по подписке

Черновик от 23.10.2026. Цель — запустить платный сервис почти без бюджета, на том, что уже есть: код студии, VPS, Prodamus, ключ GigaChat. Цены и сроки ниже — оценки, не обещания. Цены сторонних сервисов приблизительные, их нужно проверить перед оплатой.

| Компонент | Сейчас в коде | План |
|---|---|---|

| Генерация текста КП | ✅ ProxyAPI, GigaChat, YandexGPT (`LLM_PROVIDER`) | по умолчанию GigaChat/YandexGPT |

## 2. Архитектура (минимальная)

- Один процесс Python (текущий `studio.web` переписать на FastAPI или оставить stdlib-сервер, добавив роуты) + фоновый воркер в том же контейнере (очередь в БД, без Redis).
- БД: SQLite (WAL) на старте — ноль памяти сверху и ноль администрирования. Переход на PostgreSQL — когда появятся десятки активных пользователей.
- PDF создаются на сервере тем же `render_pdf`, хранятся на диске VPS: `/data/<tenant_id>/<job_id>/*.pdf`, срок хранения — например 30 дней, потом удаление.
- Caddy или nginx как reverse proxy с бесплатным TLS (Let's Encrypt).
- Генерация по одному клиенту за раз (как сейчас), очередь — общая, с лимитом параллельности 1–2.

## 3. Хостинг

**Текущий VPS 77.233.215.177:** ~894 МБ RAM, Docker. Чего ждать:
- Python + ReportLab + pandas ≈ 150–250 МБ на процесс (оценка, замерить). Docker сам съедает часть памяти. Postgres на таком сервере — лишний; SQLite.
- pandas для чтения таблиц — самая тяжёлая часть; можно заменить на `csv` + `openpyxl` в read-only режиме.
- Обязательно swap 1–2 ГБ, лимит памяти контейнера (`mem_limit`), один воркер.
- Генерация текста идёт на стороне GigaChat/YandexGPT — CPU сервера нагружает только PDF.
- Вывод: для MVP и первых платящих пользователей хватит. Узнать, где физически стоит сервер (для 152-ФЗ нужен ЦОД в РФ).

## 4. Вход

1. **Telegram Login Widget** — бесплатно, без SMS и паролей; проверка подписи `hash` по токену бота на сервере. Целевая аудитория (малый бизнес, фрилансеры) почти вся в Telegram.
2. **Вход по ссылке на email (magic link)** — для тех, у кого нет Telegram или нужен email для чеков. Отправка писем: бесплатный лимит у российского SMTP (например, Unisender Go / SMTP Яндекс 360 — проверить лимиты и условия).
- Сессия — подписанная cookie (HttpOnly, Secure, SameSite=Lax). Ссылка одноразовая, живёт 15 минут.

## 5. Оплата — Prodamus

- Олег уже работает с Prodamus: используем платёжную страницу и раздел «Подписки» (рекуррентные списания).
- Поток: пользователь выбирает тариф → ссылка на оплату Prodamus с `customer_extra`/`order_id` = id пользователя → webhook (уведомление) на `POST /webhooks/prodamus` → проверка подписи (HMAC по секретному ключу Prodamus) → продление `subscription.paid_until`.
- Отмена подписки — через Prodamus и кнопку в кабинете; при неуспешном списании — 3 дня grace-периода, потом тариф «Бесплатный».
- Чеки 54-ФЗ — в настройках Prodamus (проверить, что включены).
- Комиссия Prodamus — по текущему договору Олега, в расходы закладывается процент с оборота.

## 6. 152-ФЗ — минимум (не юридическая консультация)

- Сервис обрабатывает персональные данные: контактные лица клиентов пользователей и данные самих пользователей. Олег — оператор по отношению к данным пользователей и, скорее всего, обработчик по поручению по отношению к их клиентам (оформить в оферте).
- **Уведомление в Роскомнадзор** об обработке ПДн — до начала обработки, бесплатно, через портал pd.rkn.gov.ru.
- **Политика обработки ПДн** — опубликовать на сайте; **согласие** на обработку при регистрации (отдельная галочка), **оферта** с поручением на обработку.
- **Хранение в РФ**: БД и файлы — на VPS в российском ЦОДе; модель — GigaChat или YandexGPT. ProxyAPI в веб-версии не включать по умолчанию (зарубежные модели).
- Минимизация: не хранить исходные таблицы после генерации, удалять PDF по сроку, не писать ПДн в логи (в коде уже не пишутся ответы провайдера и ключи).
- Перед запуском — показать документы юристу хотя бы один раз (это реальный расход или услуга по бартеру).

## 7. Модель данных (multi-tenant)

```
users(id, tg_id NULL, email NULL, name, created_at)
tenants(id, owner_user_id, title, company_details_json, logo_path)   -- «студия» пользователя, реквизиты для PDF
memberships(tenant_id, user_id, role)                                  -- на будущее, в MVP один владелец
subscriptions(tenant_id, plan, status, paid_until, prodamus_id)
payments(id, tenant_id, amount, status, raw_webhook_hash, created_at)
jobs(id, tenant_id, source, status, created_at, finished_at)           -- source: web | api | tg_audit
proposals(id, job_id, tenant_id, company, status, pdf_path, error, tokens_used)
api_tokens(id, tenant_id, token_hash, name, created_at, revoked_at)
usage(tenant_id, month, proposals_count)
```
Каждый запрос к БД фильтруется по `tenant_id` текущей сессии; файлы — в папке тенанта; скачивание — только через проверку прав, без прямых ссылок.

## 8. Тарифы и лимиты (идея, цифры обсуждаются)

| Тариф | Что входит | Цена |
|---|---|---|
| Бесплатный | 5 КП в месяц, водяной знак «Черновик» | 0 |
| Старт | 50 КП в месяц, свои реквизиты и логотип | ~490 ₽/мес (гипотеза) |
| Про | 300 КП в месяц, API, интеграция с ботом | ~1490 ₽/мес (гипотеза) |

Лимиты считать в КП, а не в токенах: понятно пользователю. Себестоимость одного КП — посчитать по реальному расходу токенов GigaChat/YandexGPT после первых 100 генераций (поле `tokens_used`), до этого цифр не называть.

## 9. Интеграция с ботом «аудит потерь заявок»

1. Пользователь проходит анкету в Telegram-боте (ниша, каналы заявок, сколько теряется, бюджет).
2. Бот собирает **AI-карточку** (кратко: проблема, где теряются заявки, что предложить).
3. Бот вызывает студию: `POST /api/v1/proposals` с `Authorization: Bearer <api_token тенанта>` и JSON `{company, contact, needs, budget, source: "tg_audit", audit_card: {...}}`.
4. Студия ставит задачу в очередь, отвечает `202 {job_id}`; по готовности — webhook боту или опрос `GET /api/v1/jobs/{id}`.
5. Бот отправляет PDF в чат пользователю (и/или Олегу как лид).
- В промпте `audit_card` передаётся как данные, а не инструкции — так же, как сейчас данные клиента.
- Согласие на обработку ПДн — в начале анкеты, до вопросов.
- Сейчас: в студии нет API и токенов; есть функция `generate` + `render_pdf`, которые API будет вызывать.

## 10. MVP — что входит

Входит: вход через Telegram, загрузка таблицы и одиночная форма «один клиент», генерация через GigaChat, PDF с реквизитами пользователя, история КП, тарифы Бесплатный/Старт через Prodamus, API-токен + эндпоинт для бота, политика и согласие.
Не входит: команды, редактор шаблонов, email-вход (вторая очередь), YandexGPT как выбор пользователя, аналитика.

## 13. Риски

- 894 МБ RAM: при одновременной загрузке больших таблиц возможен OOM — лимит размера файла (уже 5 МБ и 100 строк) и одна задача за раз.
- Бесплатный лимит GigaChat может закончиться — нужен переключатель на YandexGPT (уже есть в коде).
- Качество текста российских моделей нужно сравнить с текущим на тех же 7 тестовых клиентах до запуска.
- Ответственность за ПДн: без уведомления РКН и политики сервис не запускать публично.
